      <ul>
        <li><b>Problem:</b> Synchronous APIs buckle under traffic spikes: database locks, timeouts, crashes.</li>
        <li><b>Solution:</b> A FastAPI gateway validates each <code>/transfer</code> request, publishes it to a RabbitMQ (CloudAMQP) queue and responds immediately; a Pika worker consumes at a controlled pace and acknowledges each job only after processing.</li>
        <li><b>Impact:</b> Request latency is decoupled from processing time, and unacknowledged jobs stay queued instead of being lost if a worker fails.</li>
        <li><b>Highlight:</b> Chaos test fired 50 burst requests: the gateway accepted all 50 in under a second while the worker drained the queue steadily.</li>
      </ul>

      <ul>
        <li><b>Problem:</b> Databases trust anyone with write access; a direct edit by an insider leaves no trace in the application.</li>
        <li><b>Solution:</b> Each transaction's sender, receiver, amount and timestamp are hashed with SHA-256 and stored alongside the record in MongoDB Atlas; an audit run recomputes and compares every hash.</li>
        <li><b>Impact:</b> Any record altered outside the app is flagged as tampered on the next audit: blockchain-style integrity without running a blockchain.</li>
        <li><b>Highlight:</b> A built-in insider-attack simulator edits records directly in the database to prove detection end to end.</li>

`Mar 2026` · Python · Pandas · Customer Segmentation · Uplift Testing

- **Situation:** A supermarket client's Category Manager needed to understand who buys chips and whether a new store layout was working.
- **Task:** Identify the customer segments driving sales and evaluate a store layout trial against comparable stores.
- **Action:** Cleaned and merged transaction and customer data in Python (Pandas), segmented customers by life stage and premium status, matched each trial store to a control store on pre-trial sales and customer counts, and tested the uplift for statistical significance.
